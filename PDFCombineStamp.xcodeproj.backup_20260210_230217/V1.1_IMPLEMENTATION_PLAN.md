## 🎯 Features

### Feature F-01: Drag-and-Drop Interface
**Status:** Planned  
**Priority:** High  
**Effort:** Medium (3-4 days)

#### Description
Replace the Finder-first workflow with an in-app drop zone that accepts PDF and image files. Once files are dropped, present the same options UI currently shown in the Quick Action extension.

#### User Flow
1. User launches PDFCombineStamp app (instead of right-clicking in Finder)
2. App displays a prominent drop zone: "Drop PDFs and images here"
3. User drags files from Finder to the drop zone
4. App validates files and shows the options UI (prefix, starting number, etc.)
5. User configures options and clicks "Process"
6. App combines and stamps files, saving to Desktop or user-selected location

#### Technical Implementation

**New Components:**
- `DropZoneView.swift` - Main drag-and-drop target view
- `FileListView.swift` - Display selected files with metadata
- `MainProcessingView.swift` - Orchestrates drop zone → options → processing flow

**Changes to Existing Files:**
- `ContentView.swift` - Replace info view with drop zone when no files present
- `BatesStampView.swift` - Refactor to accept file list as input parameter
- `PDFManager.swift` - Ensure it can be called from main app context

**Key APIs:**
```swift
// SwiftUI drop support
.onDrop(of: [.fileURL], isTargeted: $isTargeted) { providers in
    // Handle dropped files
}

// Validate file types
func validateFile(_ url: URL) -> Bool {
    let ext = url.pathExtension.lowercased()
    return ["pdf", "jpg", "jpeg", "png", "tif", "tiff"].contains(ext)
}
```

**Entitlements Required:**
- ✅ Already have `com.apple.security.files.user-selected.read-write`
- ✅ Already have `com.apple.security.files.downloads.read-write`

**Testing:**
- [ ] Drop single PDF
- [ ] Drop multiple PDFs
- [ ] Drop mixed PDFs and images
- [ ] Drop invalid file types (should reject gracefully)
- [ ] Drop from different locations (Desktop, Documents, Downloads, external drives)
- [ ] Process files and verify output

**Implementation Steps:**
1. Create `DropZoneView.swift` with styled drop target
2. Implement `.onDrop()` handler with file validation
3. Create `FileListView.swift` to display selected files
4. Update `ContentView.swift` to show drop zone by default
5. Connect drop zone to existing `BatesStampView.swift`

**Acceptance Criteria:**

5. Optional: Show page count for each file to help with ordering decisions

- `FileRowView.swift` - Individual row with drag handle and metadata

**Changes to Existing Files:**

- `ExtensionView.swift` - Add reordering UI to extension
- `BatesStampView.swift` - Add reordering UI to main app
- `PDFManager.swift` - Accept explicit file order parameter

**Key APIs:**
```swift
// SwiftUI drag-to-reorder
@State private var files: [URL] = []

List {
    ForEach(files, id: \.self) { file in
        FileRowView(file: file)
    }
    .onMove { source, destination in
        files.move(fromOffsets: source, toOffset: destination)
    }
}
.environment(\.editMode, .constant(.active))
```

**Alternative Implementation (More Control):**
```swift
// Custom drag gesture for each row

            // Calculate new position
        }
        .onEnded { gesture in
            // Reorder array
        }
)
```

### Feature F-03: Presets and Profiles
**Status:** Planned  
**Priority:** High  
**Effort:** Medium (4-5 days)

#### Description
Save reusable templates for prefix, starting number, output naming, and stamp settings. Include import/export as JSON for team sharing.

#### User Flow
1. User configures options (prefix, starting number, stamp position, etc.)
2. User clicks "Save as Preset" button
3. User enters preset name
4. Preset is saved and appears in preset picker
5. Later: User selects preset from picker, all settings auto-populate
6. User can export presets to share with team
7. User can import presets from JSON file

#### Data Model

```swift
struct StampPreset: Codable, Identifiable {
    let id: UUID
    var name: String
    var prefix: String
    var startingNumber: Int
    var outputFilename: String
    var stampPosition: StampPosition // top-right, bottom-right, etc.
    var fontSize: Double
    var fontColor: CodableColor
    var includeDateTime: Bool
    var dateFormat: String?
    var customLabel: String?
    var createdDate: Date
    var modifiedDate: Date
}

enum StampPosition: String, Codable {
    case topLeft, topCenter, topRight
    case bottomLeft, bottomCenter, bottomRight
}

struct CodableColor: Codable {
    var red: Double
    var green: Double
    var blue: Double
    var alpha: Double
}
```

#### Technical Implementation

**New Components:**
- `PresetManager.swift` - CRUD operations for presets
- `PresetPickerView.swift` - UI for selecting presets
- `PresetEditorView.swift` - UI for creating/editing presets
- `PresetImportExportView.swift` - Import/export functionality

**Storage:**
- Use `UserDefaults` for simplicity in v1.1
- Store as JSON array in `com.company.pdfcombinestamp.presets` key
- Alternative: Use `FileManager` to save to Application Support directory

```swift
class PresetManager: ObservableObject {
    @Published var presets: [StampPreset] = []
    
    private let userDefaultsKey = "savedPresets"
    
    init() {
        loadPresets()
    }
    
    func loadPresets() {
        guard let data = UserDefaults.standard.data(forKey: userDefaultsKey),
              let decoded = try? JSONDecoder().decode([StampPreset].self, from: data) else {
            presets = []
            return
        }
        presets = decoded
    }
    
    func savePresets() {
        guard let encoded = try? JSONEncoder().encode(presets) else { return }
        UserDefaults.standard.set(encoded, forKey: userDefaultsKey)
    }
    
    func addPreset(_ preset: StampPreset) {
        presets.append(preset)
        savePresets()
    }
    
    func deletePreset(_ preset: StampPreset) {
        presets.removeAll { $0.id == preset.id }
        savePresets()
    }
    
    func updatePreset(_ preset: StampPreset) {
        if let index = presets.firstIndex(where: { $0.id == preset.id }) {
            presets[index] = preset
            savePresets()
        }
    }
    
    // Import/Export
    func exportPreset(_ preset: StampPreset) -> Data? {
        try? JSONEncoder().encode(preset)
    }
    
    func exportAllPresets() -> Data? {
        try? JSONEncoder().encode(presets)
    }
    
    func importPresets(from data: Data) -> Result<[StampPreset], Error> {
        do {
            let imported = try JSONDecoder().decode([StampPreset].self, from: data)
            return .success(imported)
        } catch {
            return .failure(error)
        }
    }
}
```

#### 2. Error Handling
**Current:** Generic error messages  
**Improved:**
- Specific error messages with solutions
- Recoverable errors allow retry
- Log errors for debugging

**Error Categories:**
```swift
enum PDFError: LocalizedError {
    case fileNotFound(String)
    case fileNotReadable(String)
    case invalidPDF(String)
    case insufficientPermissions(String)
    case outOfMemory
    case outputLocationNotWritable(String)
    case processingFailed(String, underlyingError: Error?)
    
    var errorDescription: String? {
        switch self {
        case .fileNotFound(let filename):
            return "File not found: \(filename)"
        case .fileNotReadable(let filename):
            return "Cannot read file: \(filename). Check file permissions."
        case .invalidPDF(let filename):
            return "\(filename) is not a valid PDF file."
        case .insufficientPermissions(let location):
            return "Cannot access \(location). Grant permission in System Settings > Privacy & Security."
        case .outOfMemory:
            return "Not enough memory to process these files. Try processing fewer files at once."
        case .outputLocationNotWritable(let location):
            return "Cannot save to \(location). Choose a different location."
        case .processingFailed(let message, let error):
            return "Processing failed: \(message)\n\(error?.localizedDescription ?? "")"
        }
    }
    
    var recoverySuggestion: String? {
        switch self {
        case .insufficientPermissions:
            return "Go to System Settings > Privacy & Security and grant access."
        case .outOfMemory:
            return "Try processing fewer files, or restart the app."
        case .outputLocationNotWritable:
            return "Try saving to Desktop or Documents folder."
        default:
            return nil
        }
    }
}
```

## 🎓 Developer Notes

### Key Design Decisions

1. **Preset Storage: UserDefaults vs. Files**
   - **Decision:** UserDefaults with App Groups
   - **Rationale:** Simpler, automatic syncing between app and extension, sufficient for expected data size
   - **Alternative:** File-based storage in Application Support (consider for v1.2 if presets grow large)

2. **Reordering: .onMove() vs. Custom Gesture**
   - **Decision:** `.onMove()` for simplicity
   - **Rationale:** Native SwiftUI, good accessibility support, less code
   - **Alternative:** Custom drag gesture if more control needed

3. **Drop Zone: Replace ContentView vs. Add Tab**
   - **Decision:** Replace ContentView (show drop zone when no files)
   - **Rationale:** Simpler UX, single-purpose app
   - **Alternative:** Tab-based interface for future expansion

### Code Style Guidelines
- Use SwiftUI for all new UI
- Follow existing naming conventions
- Add documentation comments for public APIs
- Use `// MARK:` to organize code sections
- Prefer value types (struct) over reference types (class) where appropriate

### Testing Approach
- Unit test business logic (PresetManager, validation)
- Integration test user flows (drop → reorder → process)
- Manual test edge cases and errors
- Performance test with realistic file counts
